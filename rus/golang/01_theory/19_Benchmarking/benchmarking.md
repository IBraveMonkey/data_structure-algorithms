# ⏱️ Бенчмарки и Профилирование в Go

**Бенчмаркинг** — это процесс измерения производительности кода. В Go это встроенная возможность пакета `testing`, которая позволяет узнать, сколько времени занимает операция и сколько памяти она потребляет.

---


# 1. 📝 Основы бенчмаркинга

Бенчмарки пишутся в файлах `_test.go` и имеют сигнатуру `func BenchmarkXxx(b *testing.B)`.


### Пример простого бенчмарка:

```go
func BenchmarkMyFunction(b *testing.B) {
    for i := 0; i < b.N; i++ {
        MyFunction()
    }
}
```

- **`b.N`**: Это магическое число, которое Go подбирает автоматически. Он запускает цикл столько раз, сколько нужно, чтобы получить статистически значимый результат (обычно это занимает около 1 секунды).


### Как запускать:
```bash
go test -bench=.          # Запустить все бенчмарки
go test -bench=MyFunc     # Запустить конкретный бенчмарк
go test -bench=. -benchmem # Показать аллокации памяти
```

---


# 2. 🛠️ Инструменты управления временем

Иногда подготовка к тесту занимает больше времени, чем сам тест. Чтобы результат был честным, используйте методы `b`:

- **`b.ResetTimer()`**: Сбрасывает накопленное время. Вызывайте после тяжелой подготовки.
- **`b.StopTimer()` / `b.StartTimer()`**: Позволяют исключить из замера конкретные участки кода.
- **`b.ReportAllocs()`**: Включает отчет об аллокациях прямо в коде (аналог флагу `-benchmem`).

```go
func BenchmarkComplex(b *testing.B) {
    data := prepareHugeData() // Тяжелая подготовка
    b.ResetTimer()            // Игнорируем время подготовки

    for i := 0; i < b.N; i++ {
        Process(data)
    }
}
```

# 3. ⚠️ Best Practices (Как не обмануть себя)


### 1. Избегайте оптимизаций компилятора 🧠
Если результат функции нигде не используется, компилятор может просто "выкинуть" вызов функции, и бенчмарк покажет 0 нс.

**Плохо:**
```go
func BenchmarkBad(b *testing.B) {
    for i := 0; i < b.N; i++ {
        fmt.Sprintf("hello %d", i) // Компилятор может это оптимизировать
    }
}
```

**Хорошо (используйте глобальную переменную):**
```go
var result string

func BenchmarkGood(b *testing.B) {
    var r string
    for i := 0; i < b.N; i++ {
        r = fmt.Sprintf("hello %d", i)
    }
    result = r // Записываем в глобальную переменную, чтобы компилятор не удалил код
}
```


### 2. Параллельные бенчмарки 🚀
Если вы хотите проверить, как код ведет себя под нагрузкой из множества горутин:

```go
func BenchmarkParallel(b *testing.B) {
    b.RunParallel(func(pb *testing.PB) {
        for pb.Next() {
            MyConcurrentFunc()
        }
    })
}
```

# 4. 🔍 Профилирование (pprof)

Если бенчмарк показал, что код медленный, нужно понять **почему**. Для этого в Go есть `pprof`.


### Типы профилей:
1. **CPU Profile**: Где процессор проводит больше всего времени.
2. **Heap (Memory) Profile**: Кто аллоцирует память и где она живет.
3. **Alloc Profile**: Все выделения памяти (даже если она уже очищена GC).
4. **Goroutine Profile**: Состояние всех горутин.
5. **Mutex/Block Profile**: Где программа стоит в ожидании блокировок.


### Как снять профиль из бенчмарка:
```bash
go test -bench=. -cpuprofile=cpu.prof -memprofile=mem.prof
```


### Как смотреть результат:
```bash
# Веб-интерфейс (самый удобный способ)
go tool pprof -http=:8080 cpu.prof

# Интерактивный режим в консоли
go tool pprof cpu.prof
(pprof) top10      # Топ-10 функций по времени
(pprof) list Func  # Подробный разбор функции по строчкам
```

---


# 5. 📽️ Execution Trace (`runtime/trace`)

Если `pprof` показывает агрегированные данные, то `trace` показывает **таймлайн**: как работали горутины, когда включался GC, на каких ядрах выполнялся код.

**Запуск:**
```bash
go test -bench=. -trace=trace.out
go tool trace trace.out
```

---


# 6. 🎓 Продвинутые советы

- **Inlining**: Проверяйте, не слишком ли большая ваша функция для инлайнинга (`go build -gcflags="-m"`).
- **Escape Analysis**: Понимайте, уходит ли переменная в кучу (heap). Аллокации в стеке практически бесплатны.
- **Benches vs Tests**: Бенчмарки — это НЕ тесты. Они не должны проверять корректность, только скорость.
- **Стабильность окружения**: Не запускайте бенчмарки на ноутбуке, который в это время обновляет систему или подключен к разным источникам питания (частота CPU может скакать).

---


### 📊 Что проверять в первую очередь?
| Проблема | Инструмент | Флаг / Команда |
| :--- | :--- | :--- |
| Общая скорость | `testing.B` | `go test -bench=.` |
| Утечки / Аллокации | Mem Profile | `go test -benchmem` |
| Простой в блокировках | Mutex Profile | `-mutexprofile=mutex.out` |
| Непонятное поведение | Trace | `-trace=trace.out` |
