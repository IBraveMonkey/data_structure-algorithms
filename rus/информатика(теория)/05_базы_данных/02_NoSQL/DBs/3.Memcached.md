## 1. 🤔 Что это? (Просто Кэш)

**Memcached** — это дедушка всех кэшей. Это распределенное хранилище типа **Key-Value** в оперативной памяти.

*   **Примитивный**: Умеет только `SET`, `GET`, `DELETE`. Никаких списков, сетов или сортировок.
*   **LRU (Least Recently Used)**: Когда память заканчивается, он удаляет те данные, которые давно не спрашивали.
*   **Волатильность**: Если выключить сервер, все данные пропадут. Никаких сохранений на диск (как RDB/AOF в Redis).

---


## 2. ⚡ Архитектура (Multithreading)

Главное отличие от Redis — **Многопоточность**.

*   **Redis**: Однопоточный. Одно ядро процессора на 100%.
*   **Memcached**: Многопоточный. Может утилизировать все 64 ядра вашего мощного сервера.

Это делает Memcached идеальным для **простого кэширования мелких объектов** (HTML-фрагменты, сессии, результаты SQL-запросов) на очень высоких нагрузках, где Redis может упереться в процессор.

---


## 3. 🥊 Memcached vs Redis

| Фича | 🧠 Memcached | 🍒 Redis |
| :--- | :--- | :--- |
| **Типы данных** | Только String | String, List, Set, Hash, Stream... |
| **Потоки** | Multi-threaded | Single-threaded |
| **Персистентность** | Нет (все в RAM) | Есть (RDB, AOF) |
| **Кластеризация** | На клиенте (Client-side) | Redis Cluster (Server-side) |
| **Сложность** | Очень просто | Комбайн |

---


## 💡 Итог
В 2024 году Redis почти всегда лучше, потому что он умеет всё, что умеет Memcached, и еще вагон всего сверху.
Но если у вас супер-простая задача (хранить сессии) и гигантская нагрузка, которую нужно размазать по ядрам CPU — Memcached всё еще жив.
