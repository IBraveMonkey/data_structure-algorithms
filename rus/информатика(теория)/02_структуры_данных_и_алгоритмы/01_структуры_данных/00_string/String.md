# 🧵 Строки (Strings)

**Описание**: 
Строка — это фундаментальная структура данных, представляющая собой последовательность символов. В современной информатике строки рассматриваются не просто как текст, а как абстракция над массивом байтов с определенными правилами интерпретации и управления памятью.

---


## 🏗️ Внутреннее устройство

На низком уровне существует два основных подхода к представлению строк в памяти:

1.  **Null-terminated (строки в стиле C)**:
    *   **Как это работает**: Символы идут один за другим, а конец строки помечается специальным "нулевым" байтом (`\0`).
    *   **Плюсы**: Экономия памяти (всего 1 байт на маркер конца).
    *   **Минусы**: Чтобы узнать длину строки, нужно пройти её всю (сложность $O(n)$). Это также создает риски безопасности (переполнение буфера).

2.  **Length-prefixed (строки в стиле Pascal/Go/Java)**:
    *   **Как это работает**: В начале (в дескрипторе строки) хранится целое число — её длина.
    *   **Плюсы**: Мгновенное получение длины ($O(1)$) и высокая безопасность.
    *   **Минусы**: Занимает чуть больше памяти под хранение метаданных (дескриптора).


### 🧱 Иерархия: Байт vs Символ
Современные строки — это чаще всего последовательность байтов, интерпретируемая через **кодировку**:
*   **ASCII**: 1 байт на символ. Ограничена латиницей и базовыми символами.
*   **Unicode (UTF-8)**: Переменная длина (от 1 до 4 байтов). Самый популярный формат в веде и современных языках.
*   **UTF-16/UTF-32**: Фиксированная или полуфиксированная ширина, чаще используется во внутренних системных API (например, в Windows или Java/C#).

> [!IMPORTANT]
> Длина строки в байтах и количество видимых символов — это разные вещи. Например, смайлик 🐵 занимает 4 байта в UTF-8, но считается одним символом.

## 🔒 Принцип Неизменяемости (Immutability)

Во многих современных языках (Java, Python, Go, JavaScript) строки являются **неизменяемыми**.

**Зачем это нужно?**
1.  **Безопасность**: Строка не изменится "под капотом", пока вы передаете её между функциями или потоками.
2.  **Оптимизация (Интернирование)**: Система может хранить только одну копию одинаковых строк в памяти для экономии ресурсов.
3.  **Кэширование Хэша**: Поскольку строка не меняется, её хэш можно вычислить один раз, что ускоряет использование строк в качестве ключей в HashMap/Dictionaries.

## 💻 Реализация

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	// В Go строка — это неизменяемый массив байтов
	s := "Привет, Gopher! 🐹"

	// 1. len() возвращает длину В БАЙТАХ (O(1))
	fmt.Printf("Байтов: %d\n", len(s)) 

	// 2. RuneCount возвращает количество СИМВОЛОВ (O(n))
	fmt.Printf("Символов: %d\n", utf8.RuneCountInString(s))

	// 3. Прямой доступ по индексу s[0] вернет БАЙТ, а не символ
}
```

```javascript
// В JavaScript строки также неизменяемы и используют UTF-16
const s = "Привет, Gopher! 🐹";

// 1. .length возвращает количество 16-битных кодовых единиц
console.log(`Длина (code units): ${s.length}`); 

// 2. Для корректного подсчета символов (включая эмодзи)
console.log(`Символов: ${[...s].length}`);

// 3. Доступ по индексу вернет символ (или часть суррогатной пары)
console.log(`Первый символ: ${s[0]}`);
```


### Эффективная работа
Поскольку строки неизменяемы, операция `s = s + "more"` внутри цикла создает новую строку на каждой итерации. Это крайне медленно ($O(n^2)$).
Для сборки строк следует использовать специальные буферы (например, `strings.Builder` в Go или `StringBuilder` в Java).

---


## 🚀 Алгоритмы и сложности

| Операция | Сложность (Length-prefixed) | Сложность (Null-terminated) |
| :--- | :--- | :--- |
| **Получение длины** | $O(1)$ | $O(n)$ |
| **Доступ по индексу** | $O(1)$ (к байту) | $O(n)$ (нужно считать до индекса) |
| **Конкатенация** | $O(n+m)$ | $O(n+m)$ |
| **Поиск подстроки** | $O(n \cdot m)$ (наивный) | $O(n \cdot m)$ |

**Популярные алгоритмы**:
*   **Кнута-Морриса-Пратта (KMP)**: эффективный поиск подстроки за $O(n+m)$.
*   **Бойера-Мура**: используется в большинстве стандартных библиотек для быстрого поиска.
